# TrendScope 1.0.0 发布说明

发布日期:2026-09-27 · 版本号来源:`package.json`(侧栏、启动日志、`npm run doctor` 同源引用)
形态:本地运行的桌面 Web 应用(浏览器打开本机端口),数据落在本机 SQLite 文件。

---

## 1. 怎么开始用

```bash
npm install
npm run build
npm start          # http://localhost:5184
```

想看完整效果而不想先准备数据:`npm run demo`(端口 5185,独立演示库,不碰正式库)。
装好后先体检:`npm run doctor`(Node 版本 / 原生模块 / 数据目录可写 / 迁移状态 / 三项密钥 /
端口 / 构建产物 / 备份可用性)。

## 5. 已知限制

1. 词法基线是字符级近似:话题关键词可能出现重叠片段,话题名偏“关键词拼盘”;文本相同或高度
   相似的**不同簇不会自动合并**,合并始终需要人工确认。配置向量服务后质量提升。
2. 指数与结论描述的是“内容之间的相对表现”,不是因果,也不是选题建议;界面不提供此类措辞。
3. 演示库、正式库共用同一套代码路径,但正式库里如果还留着 QA 导入的示例批次,首页会显示
   “演示 / 回放数据占比”横幅 —— 这是刻意保留的提示,不是数据损坏。
4. `better-sqlite3` 的原生二进制与 Node ABI 绑定:切换 Node 大版本后若报 `NODE_MODULE_VERSION`
   不匹配,在 `node_modules/better-sqlite3` 目录执行
   `node node_modules/prebuild-install/bin.js` 即可,无需编译环境。
5. 只支持单人本机使用:没有多用户、权限、并发写入协调。

## 6. 备份与还原

```bash
npm run db:backup                      # 在线备份 + 逐项校验(完整性 / 表数 / 行数)
npm run db:backup -- --checkpoint      # 备份后折叠 WAL,得到自包含单文件
npm run db:backup -- --verify-only     # 只校验最近一份备份
```

备份落在 `data/backup/`。还原 = 停止应用 → 用备份文件替换 `data/trendscope.db`(并确保
`-wal` / `-shm` 一并删除或来自同一次折叠)→ 重新启动(启动会自动校验并记账迁移)。
迁移失败会整体回滚,报错信息里会指出是哪一份迁移、以及如何使用最近备份还原。

## 7. 本次交付中做出的、可能被推翻的判断

以下不是“正确答案清单”,而是我在信息不完整时做的取舍,列出依据与推翻后果,便于评审翻案:

1. Studio 生成用 `wait:true` 同步返回,而不是 202 + 后台任务 —— 单次调用秒级,UI 需要立刻拿到方案。
2. 无凭据时 `generate` 返回 409 而非 200 + 确定性摘要 —— 避免前端把摘要误标成 AI 结果。
3. 确定性证据摘要不写入方案历史表 —— 历史只针对“生成的方案”,摘要可重算。
4. 人工标记只有 保存 / 收藏 / 丢弃(+取消),没有“发布” —— 规格明确禁止自动发布。
5. 证据指纹不包含“由当前时钟推算的新鲜度” —— 包含则同一份证据永远无法复用(实测过)。
6. 历史导入批次名在界面映射成中文前缀,不改写数据库中的原始名字 —— 批次名属于只追加历史。
7. 枚举的原始 code 保留在 `title` 悬停提示 —— 排查采集 / 导入问题需要真实取值。
8. 破坏性操作(删除任务 / 归档模型 / 确认合并)保留一次 `window.confirm` —— 输入用对话框、
   确认用原生弹窗是常见分工,而“死按钮”才是本轮要消灭的对象。
9. 词法关键词里的 `fixture`、重叠片段按“数据”处理,不按界面文案缺陷处理 —— 来自演示语料本身。
10. 全角 / 半角标点未强制统一(本轮新增文案用半角)—— 属排版审美,批量替换有改错数据文案的风险。
11. 侧栏显示的数据文件路径由“当前进程实际打开的文件”决定,而不是库名常量 ——
    WP4 走查发现正式实例曾显示演示库名,已修并加回归测试。
12. 导航去掉 `01…12` 与页头 `NN /`、`A /`、`B /` 编号,并按用户流程重排 ——
    若评审认为视觉识别度下降,可改成图标分组,但不宜回到阶段编号。
13. §120 的集中配置放在**新增的「设置」页**,而不是塞进首页(首页要保持短);
    工作室与语义中心只留一行状态 + 跳转,避免同一份配置在两个页面各说一遍。
14. 数字口径固定为“计数用千分位精确值 / 指标与坐标轴用万亿”,而不是把所有数字都塞进同一个函数 ——
    概览值与可核对的精确值用途不同;两处阈值由 `fmtMetric` 与 `fmtAxisNumber` 共享并有回归断言。
15. 中文逐字断行在 CSS 层修(表单元格按词断,只有长 ID/URL 按字符断),没有逐页改 `maxWidth` ——
    避免把同一问题修成几十处互不一致的局部补丁。
16. §113 注入用例放在**集成层**(真 HTTP + Replay),不只做 prompt 单测 ——
    只有端到端能同时证明“结构不变 + 指令未被改写 + 密钥不外泄”;
    prompt 层的 DATA 标注另有 `tests/unit/studioCore.test.ts` 覆盖。

| AI 能力来源 | 新增合法来源:**本机已登录的命令行模型**(`STUDIO_CLI_COMMAND=claude`);没有 `STUDIO_API_KEY` 也能出选题方案与 AI 话题命名,来源在设置页与工作室如实标注,密钥状态仍显示「未配置」 |
| 热点派生采集 | **新增**「按今日热点深挖内容」:热榜标题当检索词 → 知乎官方搜索取回创作内容。真机一轮 3 个检索词 → 15 条新增,正文 719–1044 字、有作者与真实赞数;库内 831 → 973 条。槽位任务恒定、缺凭证零写入、30 分钟节流、6 小时词冷却 |

| 采完即算的覆盖面 | 采集与**导入(CSV / JSON / 手工录入)**同等待遇自动补分析;示例数据导入刻意不触发 |

修出的缺陷(细节见 `docs/DECISIONS.md` D47–D50 与 `docs/TEST_STATUS.md` 2026-09-29 一节):

1. 话题聚类失败被流水线记成 `completed`(状态用返回值传递而非抛异常),自动分析因此谎报已完成;
2. 采集与分析并行收尾时"聚类开始后才入库的内容没有向量"导致聚类失败 —— 自动路径现在补一次向量再重聚;
3. `/api/hot/capture` 的 `analysis.triggered` 与 `autoAnalysis.triggered` 自相矛盾;
4. 提示词要求模型复述 `schemaVersion/promptVersion`,而严格 schema 拒绝这两个键 —— 合规方案被判非法(已修,`STUDIO_PROMPT_VERSION` 升 v2);
5. 话题命名读的是**没有 chat 接口的向量服务**,且路由里还有一份用错密钥名的手写 fetch —— 现统一到一处判定;
6. 渠道列表有「抖音热榜(聚合源)」而拒绝清单写「抖音热榜:不提供」互相打脸 —— 拒绝项改为明确指向**需伪造签名的官方私有接口**;
7. 事故遗留的 6 条 0 成员空话题里 4 条仍为 active(含 `url id body`),会虚增活跃话题数 —— 已归档(可还原,改前有快照)。

仍然没有的部分(不算失败,但使用者需要知道):

| 项 | 状态 |
| --- | --- |
| 抖音 / 小红书 / 微博的**官方私有接口** | 不提供:调用它们需要伪造平台签名或逆向风控参数,属于检测规避。公开热榜由聚合源渠道取回 |
| 未归类内容 | 765 条里约 647 条未成簇:热榜类条目只有标题+热度、缺正文与发布时间,单次采样难以成簇;随定时采集累积会改善,但**不靠放低阈值制造假簇** |
| 话题 AI 命名 | 只在**手动**点「刷新全部分析」时调用模型;自动补算仍用关键词命名(按次消耗使用者额度,不该被定时器驱动) |
| 微博登录态渠道 | 依赖使用者自己的 `WEIBO_COOKIE`(只读、单页、低频) |
| 外部 AI Key | 仍未配置;本机 CLI 是当前 AI 能力来源,外部模型可随时改用 `STUDIO_API_KEY` 顶替 |
| 派生检索词的具体内容 | 目前只有知乎一路有已授权的搜索接口(`TRENDSCOPE_HOT_CASCADE_CONNECTOR`)。抖音/小红书/微博的搜索接口需要伪造签名或逆向风控参数,不做;这三路仍以热榜标题+热度入库。B站渠道入库的是**视频**条目(播放/点赞/评论/收藏/UP主/发布时间) |
