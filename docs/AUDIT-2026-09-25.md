## 1. 运行环境(已修)

`node_modules/better-sqlite3` 的原生二进制绑定编译时的 Node ABI。交接文档要求统一用
`.workbuddy` 的 node 22,而本机默认 node 是 v24,于是 `npm test` / `npm start` 在默认
环境下直接崩在模块加载。本机无 Visual Studio,`npm rebuild` 走不通;改用
`node node_modules/prebuild-install/bin.js` 拉到 node-v137 win32-x64 官方 prebuild 解决。
现基线:**系统 node v24 下 365/365 → 修完缺陷后 419/419**。

## 2. 数据完整性:WAL 使单文件备份失效(已修)

库在 WAL 模式。实测 `data/trendscope.db` 主文件 mtime 停在 9/24 23:41,而
`trendscope.db-wal` 有 4.1 MB(9/25)。把主文件单独复制出来读取,得到的是 **23 张表、
零条 Stage 6B–9 数据**;连同 WAL 一起读才是 45 表 / 363 行。

后果:`data/backup/` 里三个"迁移前备份"都是用 `cp 主文件` 生成的,内容一致且残缺。
若按它们回滚,话题聚类、评分、情报、机会四个 Stage 的数据会静默消失。

处置:新增 `scripts/db-backup.mjs`(`npm run db:backup`),用 SQLite 在线备份 API
(读穿 WAL)+ 表数/行数/integrity 逐项校验,并支持 `--checkpoint` 把 WAL 折叠回主文件。
已对真机库执行备份 + `wal_checkpoint(TRUNCATE)`:主文件现 45 表 / 363 行 / integrity ok,
**脱离 WAL 可独立读取**(已用"复制主文件单读"的方式复验)。旧的三个残缺副本保留未删,
只在文档中标注不可当作备份。

## 3. 后端缺陷(逐条实测验证后修复)

1. **`/api/trends/topics?minOpportunity=N` → 500**。`listTopicTrends` 的 count 查询没有
   join `topic_opportunity_current`,而共享的 where 条件引用了它。
   验证:`curl` 得 `{"error":"no such column: topic_opportunity_current.score"}`。
2. **参数错误一律 500**。zod 校验失败被通用 catch 转成 500,而 `collection.ts` 同类情况
   返回 400 —— 约定不一致,证明是实现疏漏。新增 `routes/errors.ts` 统一:zod→400(中文
   摘要)、not found→404、其余 500 并落日志。
3. **`/api/analysis/full-refresh` 404**。路由定义 `/full-refresh` 挂在 `/api` 下,实际路径
   是 `/api/full-refresh`,而代码注释、`OPPORTUNITY_MODEL.md`、`TEST_STATUS.md` 三处都写
   `/api/analysis/full-refresh`。改为按文档承诺挂载。
4. **防重入锁可被绕过**。三个路由各自维护 `running` Set,且只在"后台跑"分支检查;
   `wait:true` 完全不拿锁,`full-refresh` 又直接调引擎函数、绕过各引擎自己的锁。
   验证:并发两次 `full-refresh(wait:true)` 两次都执行(202+202),`oppRuns +4 / scoringRuns +6`。
   新增 `services/engineLock.ts` 统一锁,`full-refresh` 一次占住四个引擎。
5. **`move-content` 可写入不存在的 contentItemId → 孤儿 membership 并虚增 member_count**。
   `topic_memberships` 无外键(`PRAGMA foreign_key_list` 返回 `[]`)。
   验证:沙箱里 POST `{"contentItemId":999999}` 返回 200,member_count 6→7。已加存在性校验。
6. **`collection/stats` 的"今日"其实是 90 天窗口**。WHERE 用 90 天,只有
   `recordsCollectedToday` 在 SUM 里再卡日界。验证:`runsToday:2 / recordsCollectedToday:0`
   而两条 run 都不是今天。已改为真日界,`runningNow` 单独统计。
7. **`embedding/settings` 谎报 provider**。过滤条件 `s.provider !== "lexical"`,但词法空间的
   provider 实际是 `"lexical-hash"`、`mode` 才是 `"lexical"` → 只有词法空间时也报
   `openai-compatible`。验证:响应 `provider:"openai-compatible"` 而 spaces 只有一条 lexical-hash。
   同处还有一个两支相同的死三元表达式。
8. **`topics.ts` 5 个 async handler 无 try/catch**。Express 4 不捕获 async reject,错误中间件
   也收不到 → 请求永久挂起。已补齐。
9. **排队中的 run 被取消会让任务永久卡死**。`runningTasks` 只在 `executeRun` 的 finally 释放,
   而 queued-cancel 分支根本不进 `executeRun` → 之后每次 `runTask` 都返回 already_running,
   只能重启进程。已在取消分支释放锁;顺带补 `runCache` 的泄漏(原先只写不删)。
10. **分页/排序稳定性**:`content_items` 默认排序 `collected_at DESC` 无 tie-breaker,同一次
    导入的多行时间戳完全相同 → 翻页会重复/漏项。已加 `id DESC` 次级键。
11. **`requestCancel` 对不存在的 run 返回成功**(无条件 UPDATE)。改为回传是否命中行。
12. **`createTopicIntelligenceRouter` 在 index.ts 被挂载两次**。已去重(注意:它与
    `createIntelligenceRouter` 是两个不同 router,前者提供 `/api/topics/:id/*`,不能整删)。
13. **FTS 相关度排序方向反了(潜在)**。SQLite `bm25()` 越小越相关,原实现把 `order=desc`
    映射成 `ORDER BY bm25() DESC`,即最不相关的排最前。此前 UI 从不发送 `sortBy=relevance`
    所以未暴露;已修正方向并让该能力在 Explorer 真正可用。
14. **JSON 导入预览缺 `headers`**。CSV 预览返回 `headers`,JSON 预览不返回,而前端
    `MappingEditor` 直接 `headers.map()` → 打开即 TypeError 白屏(tsc 发现不了,因为前端
    自定义类型把 `headers: string[]` 写成了必然存在)。已在服务端补齐,与 CSV 契约一致。

## 4. 前端缺陷

**最严重:`MomentumTable` 表头与单元格数量不一致(16 vs 15),两列错位。**
多出一个无对应单元格的 `内容` 表头,且 `所属话题` 的表头位置与实际单元格位置差 4。
真机截图确认:话题块渲染在"Δ收藏"列下、爆发指数渲染在"所属话题"列下、日期渲染在
"爆发指数"列下 —— 影响趋势中心动量榜与内容候选工作台两张主表。已按"表头顺序=单元格顺序"
重排,并加契约测试锁死字段集合。

其余已修:

- **话题关注/待看/忽略按钮完全失效**:前端 `POST /topics/:id/watch`,服务端只注册 `PUT` → 404,
  且调用无 try/catch,失败静默。
- **成员"移出"失效**:前端 `DELETE /topics/:id/move-content/:itemId`,服务端要的是
  `DELETE /topics/:id/move-content` + JSON body → 404。`lib/api.ts` 的 `del()` 也不支持 body。
- **候选工作台三个决策标签页内容相同**:`/picks?pageSize=200` 从不带 `status`,而后端支持。
- **深链缺失**:没有 `/topics/:id` 路由,话题详情是页内 state,因此机会工作台/趋势中心的
  "话题页 →"只能跳到列表;已加 `/topics/:id?` 单路由(避免父子双 Route 重挂载丢状态)并改深链。
- **导入后"batch 详情"链接指向不存在的路由** `/content?batch=N` → 被 `*` 兜底重定向到总览。
- **HashRouter 下用裸 `<a href="/content/N">`** → 整页加载并丢上下文;改为 `<Link>`。
- **话题洞察面板 50 ms 计时器**:两个请求只要在 50 ms 后到达,`setMiss(true)` 已触发,而
  `if (miss) return` 排在数据判断前 → 数据明明在手却永久显示"尚未运行"。改为请求落定后判定。
- **null 被渲染成 0 / 假精确**:共性表的 viralRate/median 用 `?? 0` 把"未知"显示成"0%"
  (一条并没有依据的事实断言);`fmtMetric` 对 <1 万的值直接 `String()`,日增赞显示成
  `3.4285714285714286/d`。均已改为 `—` / 一位小数。
- **采集中心"共 N 条"是当页条数**,不是总数(服务端默认 30 条上限并回传 total)。已用 total + 分页。
- **Explorer 日期上界排除结束当天**:日期控件给 `YYYY-MM-DD`,库里是完整 UTC ISO 串,
  字符串比较下 `lte("2024-05-01T08:34:37Z","2024-05-01")` 恒 false。已在服务端补成当日末尾。
- **Explorer 横幅谎称"默认按相关度排序"**,实际从不发送 `sortBy=relevance`;且表头 Author
  不在服务端 `SORTABLE` 白名单里,点击后静默退回 collectedAt 而箭头仍显示已排序。
  已补 `authorName` 到白名单、加相关度开关、横幅改为陈述实际排序。
- **治理类写操作全部无错误处理**(重命名/合并/移动/watch 都是裸 await),失败时既不提示
  也不回滚 UI。已统一经 `guard()` 捕获并显示。
- **缺失的样式 token**:`--line` 被引用但从未定义(边框不可见)、`.spin` 无动画规则、
  `mark.hl` 无定义(高亮落到浏览器默认黄底)。已补。

## 5. 前端设计

现状判断:配色与字体是有意识的"工业/纸面"体系(paper/panel/ink/amber + IBM Plex),
**概念没问题,问题在落地**:

- CSS 只有颜色 token,**没有字号/间距体系** —— 每个标题都写死 `fontSize:13/14/15/17/18/22/30`,
  层级因此是噪声。已引入 `--fs-*` / `--sp-*` 并统一 `.section-title.sub`。
- **整份样式没有一条 `@media`**。窄窗口下侧栏把内容挤到不可用。已补 4 档断点(侧栏折叠、
  栅格降列、筛选器换行、reduced-motion)。
- **宽表没有策略**:`table.ts{width:100%}` + `overflowWrap:anywhere` 使列被压到一字一行
  (Dashboard 批次表实测如此)。已给 `min-width` 让 `.table-wrap` 横向滚动,并为数字/等宽列
  设 `nowrap`,同时补 `aria-sort` 样式。
- **重复实现**:22 处手写 `<table class="ts">`、56 处 `api()` 各自处理 loading/error/empty、
  13 个徽章组件(9 个声明在页面文件内)、约 35 张 label→class 映射表、饱和度分档(34/67)
  写三遍、330 处内联 style 对 334 行 CSS。
- **内部规格编号泄漏到 UI**:`0.9 / 1.1 / 1.2 / 1.4 / 1.5`(根本没有 1.3)以及 38 处 `§NN`
  交叉引用直接显示给用户。已清除用户可见文本(代码注释保留)。
- 中英混排:表头 Title/Author/Views、筛选预设 All/Mid-tier Discovery 与全中文界面并存。表头已中文化。

未做(按"targeted 修复 + 设计系统打底"的范围界定,留待后续):
`useResource()` 统一 hook、`<DataTable>` 抽象、13 个徽章合并为一个注册表、Profile 编辑 UI。
**因此"筛选竞态"(旧请求覆盖新结果)在部分页面仍存在** —— `api()` 本身支持透传 `signal`,
缺的是各调用点没有 abort,属于一次独立重构。

## 6. 本次审查中我自己造成并已修复的事故(如实记录)

用一段 Python 正则批量清理用户可见文本里的 `§NN` 时,其中一条"删除空括号"规则
`[（(]\s*[）)]` 连带删除了代码里所有真实的空括号 `()`。影响 **16 个 `.tsx` 文件、约 350 处
语法错误**,包括 `useEffect(() =>` → `useEffect( =>`、`new Map<...>()`、IIFE 尾部的 `()`、
`useParams()`、`q.toString()`、`void load()` 等。

处置过程(可复核):
1. 先从 `~/.qoder-cn/file-history/<session>/` 找出 6 个文件的改动前快照 —— 判据是
   **把我的破坏性变换重新作用到快照上,能逐字节复现当前受损文件**,才认定它是改动前版本。
2. 交接 tarball 里的版本早于 Stage 4/7,不能用于恢复(对比后确认),因此未采用。
3. 其余按语法类别机械复原,以 `tsc` 为 oracle 迭代:286 → 31 → 7 → 0 语法错误。
4. 再补两类 `tsc` 抓不到的语义损坏:`q.toString` 缺 `()`(导致内容浏览器显示 0 条)与
   `void load;`。**这一类是靠真机浏览器逐页核对"有没有渲染出数据"才发现的,不是靠测试。**
5. 最终验证:`tsc` 0 错、`npm run build` 成功、测试全绿(修复当时为 419/419,随后补齐
   竞态与引擎锁用例后为 **426/426**,见 §7)、浏览器逐页走查
   (Explorer 恢复 24 条 / 动量表 15 表头 = 15 单元格 / 无 console 报错)。

教训(已写入 HANDOFF §6 环境坑):**不要对源码跑宽泛的正则批量替换**,尤其是会命中
`()`、`[]` 这类语法必需字符的规则;批量文本处理必须先做"能否逐字节复现"的判据校验,
并且改完必须跑真机渲染验证,因为本项目前端零测试覆盖。
